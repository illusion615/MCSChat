# 批次 29 — 调试证据持久化与保留策略

## 背景

Router 是本机调试工具，但当前的存储策略是按"生产网关"设计的，与调试用途冲突：

| 数据 | 现状 | 问题 |
|------|------|------|
| 日志 | 内存环形缓冲（2000 条），无落盘 | 进程重启即全部丢失 |
| 指标 | 纯内存 | 进程重启即归零 |
| 会话 | 落盘，但 TTL 60 分钟后被自动删除 | 隔夜就查不到昨天的会话 |
| Turn 轨迹 | 完全不记录 | 前端开发无法回溯某一轮到底收到了什么 |

根因是代码把两件事混成了一件：

- **会话还能不能继续对话**（功能性生命周期）
- **会话记录还留不留着**（调试证据）

`expiresAt` 同时控制这两者，所以会话一失效，证据也一起没了。

删除点共三处：`purgeExpired()`（启动 + 每 5 分钟）、`#validate()`（访问过期会话时顺手删除）、`close()` / `forceClose()`。

## 需求

### FR-1 证据长期保留

- FR-1.1 日志落盘，进程重启后仍可查询
- FR-1.2 会话记录不再因功能性过期而被删除
- FR-1.3 默认保留期 **30 天**，可配置
- FR-1.4 `DELETE /v1/conversations/{id}` 改为标记关闭，不再删除记录

### FR-2 手工清理

- FR-2.1 支持按时间点清理：删除**早于**指定时刻的日志 / 会话
- FR-2.2 清理操作需二次确认，并返回实际删除数量
- FR-2.3 控制台提供入口

### FR-3 调试级轨迹捕获

- FR-3.1 逐轮记录：上游请求形状、每一帧原始 Activity、归约后的下游事件、时序、错误详情
- FR-3.2 归约通道（`/v1`）与透传通道（verification）都要覆盖
- FR-3.3 **默认开启**，可在控制台设置中关闭
- FR-3.4 可下载单轮轨迹供离线分析

### FR-4 存储可见性

- FR-4.1 控制台显示各类证据的占用与条目数
- FR-4.2 显示当前保留期与调试捕获开关状态

## 安全边界

调试轨迹会落盘 answer 正文与 thought 文本，这是归约契约刻意不下发的内容。因此：

- **必须**继续剥离 `Authorization`、access token、refresh token、secret、签名密钥
- **仅**在 loopback 运行模式下允许开启
- 控制台与 README 必须明示该行为
- PKCE 授权事务的清扫**保留原样**——那是短命凭据，长期留存是安全风险，不适用保留期规则

## 验收标准

- AC-1 Router 重启后仍能查到重启前的日志
- AC-2 会话超过功能 TTL 后无法发新 turn，但记录仍在列表中且标为 `expired`
- AC-3 手工清理能按时间点删除，且返回准确数量
- AC-4 任意一轮对话结束后，能下载到包含全部 Activity 帧的轨迹文件
- AC-5 轨迹文件中不含任何 token / secret
- AC-6 关闭调试捕获后不再产生新轨迹文件
